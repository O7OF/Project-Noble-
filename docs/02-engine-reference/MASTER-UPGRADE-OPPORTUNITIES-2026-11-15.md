## How the engine limits things (read this first - it explains most of the list)
Halo's engine (Blam) allocates almost everything **once at startup into fixed-size pools** ("data arrays", "game state", "restricted allocators"). The map lists **196 `g_*_allocator` pools** [MAP] (the `t_restricted_allocation_manager` instances). Each pool has a maximum count baked in at `data_new(...)` time. That is why "more actors / more particles" is a *change of a number in a startup call plus enough memory*, not a rewrite. It is also why raising one limit can break savegames or networking: the **game state is serialized** (saves, saved films, network join) and its size must stay consistent.
**Rule for every limit raise**: (1) find the `data_new` call / allocator init, (2) raise the count, (3) check game-state total size and any fixed buffers that mirror it (network/save/film), (4) test host+client desync, saved film, save/load, (5) test on a heavy map.

## H. Why you should NOT touch some things
- Deterministic pools (B3), saved-film layout, anything inside `c_simulation_*` formats without a version bump.
- Havok world settings without testing every vehicle (A6).
- Anything where the MCC build replaced the 360 implementation (renderer, audio, networking transport, online). The 360 code explains *design*; MCC addresses must be re-found.
- Online/anti-cheat: MCC online uses Easy Anti-Cheat; Noble's community client must remain separate (existing project rule).

## I. Recommended order (value / risk)
1. **G7 engine-state inspector + B1 pool-failure logging** - tells you what limit you actually hit; makes every other item cheaper.
2. **C1 / C9 net overlay** (existing engine flags) and **E11 AI debug** - free diagnostics.
3. **A3 + A4** (objects + Forge budgets) - biggest creator impact.
4. **E1 + E3 + E8** (path iteration cap, task scripting, marines as data) - big AI gain for little code.
5. **D1 + D2** (character lighting + texture-camera) - Armory polish.
6. **A5 + A12 + C4** (32 players) - already in motion; use C4 reason tables for better errors.
7. **E7 bots**, **G1 Forge++**, **G3 Megalo compiler** - larger projects.
8. **D3-D7, F4, F9** quality-of-life toggles in Noble settings.

## J. How to turn a name into a patch (workflow)
1. Pick the retail name (this file, `engine_source_map_x360_retail.csv`, or `decompile-exports\x360-retail\functions_index.csv`).
2. Read the retail body in `decompiled_v3\` (the fixed run; `decompiled\` / `decompiled_v2\` have ~10,000 empty stubs). Note strings, constants, callees.
3. Find the MCC match: search `mcc-haloreach\hr_*.c` for the same string literals/constants; confirm by call shape. Record `hr+0xRVA`.
4. Prove by a runtime read (log the value / hook read-only) before writing.
5. Make the change as a Noble hook on `src\` (DeepSeek's lane); test: single player, host+client, save/load, saved film.
6. Write the result back to the Compendium (name -> hr+RVA table).
