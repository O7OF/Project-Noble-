## UPDATE 2026-11-11 03:30 - crash SOLVED (root cause), load time
- Root cause of the Armory GPU-driver crash: Noble found the menu map's HS GLOBALS table ~1 s after the click, but the table holds GARBAGE until the map's script starts (~12-13 s later). Noble wrote the 16 permutation pairs + seq bump into the uninitialised table; the GPU driver (nvwgf2umx) crashed. Fix in ReachArmory.cpp: the first apply waits until rr_scene_done is a real scene number (-1..63), then kFirstApplyDelayMs=500 ms; 45 s fallback. Test files (temporary, data\userdata): noble-test-skip.txt, noble-test-head.txt, noble-test-delay.txt - remove before committing.
- Load time: after Armory is opened the engine needs ~13 s to load the menu map (268 MB).
- Male default knee guard: Noble now uses flair_knees "default" for knees_default on the male body (was "kat").
- Remaining list (Tyler, then): Elite armour does not change, close-up camera framing, knife stuck to chest, flicker on piece change and at startup, black background, missing/odd pieces to recheck.
