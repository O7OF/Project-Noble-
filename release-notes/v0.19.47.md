# v0.19.47

## Mods built on a Firefight canvas now mount in Forge

Installation 04 AI Battleground and Glacier AI Battleground load and run in Forge, Firefight, or whatever mode you
picked, instead of dropping back after the loading screen.

**What was wrong.** MCC's workshop maps declare the game type of the canvas they were built on, and Reach's map
loader rejects a map whose declared type differs from the type the launch asks for. Those two mods are built on
Firefight canvases (`cex_ff_halo`, `ff60_icecave`) and declare type `0x7D2`, while a Forge or Firefight launch asks
for `0x2760`. The loader therefore returned failure, the engine unwound its launch routine, and the client sat on
the loading screen with no error.

**What Noble does now.** While the engine parses a map, Noble reads the map's requested type from the load call and
aligns the map's own declared type with it before the loader's comparison. That is the relationship MCC's manifest
provides; with it the map mounts normally and the session starts.

Also in this build:

- Firefight-canvas mods get their map info patched to a multiplayer map for Forge launches (previously they were
  skipped and the launch was refused with "map and game incompatible").
- `-no-mod-dll` runs a mod's map on Noble's own engine build, ignoring the `haloreach.dll` the mod ships.

Verified: Installation 04, Glacier, Forge World and Boneyard all start a Forge session from the workshop.
