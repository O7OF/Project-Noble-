# Project Noble v0.19.45 Release Notes

## Campaign Co-op Multiplayer Loading & Handshake Fixes
- **Prompt Guest Mission Loading in Campaign Co-op:** Fixed infinite load hang at 0-4% progress for guests in Campaign multiplayer. The guest engine now promptly dispatches Command 10 (Event: Start) after a 500ms initialization delay, triggering scenario map tag loading and establishing network session channels without stalling indefinitely for host session sync.
- **Synchronized Simulation Start (Command 11):** Guests now monitor load progress (`LoadScreen::GetProgress() >= 95%`), allow world replication to settle, and dispatch Command 11 (Simulation Start), ensuring local player simulation and biped creation sync with the host.
- **Extended Host Remote Player Wait Barrier:** The host's pre-simulation wait barrier now tracks both membership updates (packet 27) and engine channel activity (port 1000) with an expanded 45-second deadline, guaranteeing guests have ample time to load tags and join the session before the host begins the mission.

## Host-to-Peer Netcode & Relay Connection Enhancements
- **Pre-emptive Host WebSocket Relay Initialization:** The host now binds and connects to the WebSocket packet relay room (`/ws/relay2`) immediately upon match launch from the pre-game lobby, eliminating early packet drops when guest clients begin handshaking before background master server heartbeats occur.
- **Immediate Relay URL Provisioning:** `POST /api/sessions` on the master server cluster now returns `relay_url` directly on initial registration, and `MasterServerClient::DoRegister` connects immediately upon receiving the response.
- **Direct UDP NAT Hole-Punch Echo Fix:** Fixed a typo in `NetworkTransport::OnNetRecv` where the host was echoing `'PING'` instead of `'PONG'` to incoming guest NAT punches, which prevented guests from computing round-trip time (RTT) and confirming direct UDP connectivity.
- **Relay Control Frame Filtering:** Updated WebSocket relay packet handling to drop both `'PING'` and `'PONG'` control frames from the game engine queue, preventing malformed datagrams from being pushed to the Blam! engine network layer.
