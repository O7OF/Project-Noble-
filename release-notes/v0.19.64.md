# Project Noble v0.19.64 (Closed Source)

## Highlights & Fixes

### 1. Local-Only 3rd-Person Camera (Co-Op & Multiplayer Fix)
- **Simulation Isolation (`CameraThirdPerson.cpp`):** Restricted the 3rd-person unit check hook (`haloreach+0xC6948`) to return-address RVAs belonging exclusively to local camera director and first-person arms rendering paths (`c_game_director::update`, `c_saved_film_director::update`, and `first_person_weapon_should_draw`), leaving deterministic simulation callers (`player_control_get_aiming_position`) untouched.
- **Co-Op Host & Peer Stability (`LobbyPatches.cpp`, `main.cpp`):** Prevented out-of-tick `unit_update_object_nodes` calls during active networked matches and enabled co-op session abort / boot suppression across both Campaign and Firefight modes, eliminating the *"Error hosting co-op"* disconnect when toggling 3rd-person camera.

### 2. Cross-Region Matchmaking & Pre-Game Lobby Persistence
- **Multi-Region Federation (`MasterServerClient.cpp`):** Client server browser and lobby operations now query and fail over across all regional master servers (`US East`, `US West`, `UK`) in parallel, tracking each session's home regional server URL automatically.
- **No False Pre-Game Lobby Kicks (`FrontEndMenu.cpp`):** Guests connected to a lobby hosted on a different regional server (e.g., US West, US East, or UK) are no longer dropped from the pre-game lobby if a regional HTTP poll experiences latency or crosses cluster nodes, and automatically re-resolve and stay synced via both WebSocket relay and cross-region HTTP fallback.

### 3. Lower-Latency Relay & Direct UDP Handshake
- **Zero-Wait Relay Sender (`NetworkTransport.cpp`):** Replaced the `Sleep(1)` polling loop (~15.6 ms Windows timer quantization) on the WebSocket relay sender thread with a condition variable (`m_relaySendCv`) that wakes immediately when game packets, lobby control frames, chat, or voice frames are queued.
- **Fast Relay Failover & Round-Trip Direct Confirmation:** Tightened direct UDP confirmation to require verified round-trip `PING`/`PONG` or active bidirectional game traffic within `3.5s` (probing every `1.0s`), seamlessly routing gameplay and port `1001` control traffic over the low-latency WebSocket relay whenever direct UDP is blocked by NAT.
