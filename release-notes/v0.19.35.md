# Project Noble v0.19.35 Release Notes

## Multiplayer AI Duplication & Clone Spawning Fixes
- **Eliminated Duplicate / Cloned Local Spawning in `SharedTagCache`:**
  - Resolved the double-spawn bug in `SharedTagCache::ProcessPendingSpawn()`: previously, `SafeCallObjectCreate` (RVA `0x7311B8`) and `SafeCallForgeSpawn` (RVA `0x692C5C`) were both being called back-to-back for every single spawn request, creating two identical entities (a clone) directly on top of each other.
  - Refactored the placement pipeline to prefer `SafeCallForgeSpawn` in Forge edit mode, and only fall back to `SafeCallObjectCreate` if `SafeCallForgeSpawn` fails or is unavailable. Never calls both functions for a single spawn request.

- **Authoritative Multiplayer Spawning & Guest-to-Host Forwarding:**
  - In multiplayer matches, non-host clients (guests) must never spawn simulation entities locally, which otherwise creates un-networked or desynced ghost clones.
  - Wired a decoupled `SpawnForwarder` callback in `SharedTagCache`: when a guest requests an object or AI spawn in multiplayer (via the Forge Menu, Item Spawner, or DevCheats), the request is automatically formatted as a JSON control packet (`type: "spawn_request"` or `type: "dev_spawn"`) and forwarded to the match host via `NetworkTransport::SendLobbyControlJson()`.
  - The match host receives the request, spawns the entity authoritatively in the game simulation, and `haloreach.dll`'s native entity replication broadcasts the spawned biped/object cleanly to all connected clients with zero duplicates.

- **Multiplayer Scenario Script AI Placement Hook (`Hook_AiPlace`):**
  - In modded maps featuring campaign or Firefight AI (such as Firefight in Multiplayer, Forge World AI Battleground, or custom scenario mods), scenario scripts execute continuous or trigger-based `(ai_place squad_name)` routines on both host and guest machines.
  - In retail Blam! engine networking, the host also replicates newly placed actors over the wire, causing guests that run `ai_place` locally to spawn a duplicate squad right inside the replicated one (cloned/double AI, with one killable and one invincible/bugged).
  - Implemented `Hook_AiPlace` at RVA `0x6C2B10`: intercepts engine and script calls to `ai_place()`, automatically suppressing client-side execution when in an active multiplayer match as a guest. The authoritative host executes the placement and synchronizes the AI units cleanly over the wire, completely eliminating AI duplication in modded matches.

- **Per-Frame Single Execution & Input Debouncing:**
  - Clamped `DevCheats::GameTick()` and `SpawnTest::Hook_Tick()` to execute ticks, hotkeys, and spawner queues only on local player datum 0 (`a == 0`), preventing duplicate executions per frame when multiple players are present in a match.
  - Added a 300ms button debounce timer across Dev Menu action buttons ("GIVE", "SPAWN IN FRONT", F6, F7, F8, F9) to eliminate rapid double-queuing from held clicks or controller buttons.
