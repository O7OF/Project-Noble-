# Project Noble v0.19.67 (Closed Source)

### AMD Hardware & Launcher Performance Optimization
- **AMD Radeon GPU Latency Adaptation (`RX 5700 XT` / `RDNA` / `GCN`):**
  - Automatically queries the active display adapter vendor via DXGI (`VendorId == 0x1002`).
  - On AMD Radeon graphics hardware, adjusts `SetMaximumFrameLatency` to `2` (instead of forcing `1`). With DXGI discard swapchains (`DXGI_SWAP_EFFECT_DISCARD`), AMD drivers serialize CPU/GPU execution on latency 1, causing presentation pipeline bubbles and severe frame drops. Latency 2 allows the AMD Command Processor to overlap command generation smoothly, eliminating launcher and in-game micro-stutters.
- **AMD Ryzen 7 (Zen 2 / 3800X) Multi-Core Frame Pacer:**
  - Upgraded the swapchain frame rate limiter in `HookSwapChainPresent` with intelligent multi-millisecond `Sleep()` intervals and safety margins.
  - Replaces tight busy-spin loops that repeatedly polled `QueryPerformanceCounter` across Zen 2 CCX dies over the Infinity Fabric. This drops render thread CPU core utilization from 100% down to under 1%, lowering CPU package temperatures and preventing thermal/bus contention.
- **Configurable Launcher Resolution & Supersampling Toggle:**
  - Removed unconditional 1.5x menu supersampling which previously forced 1440p displays into full 4K (3840x2160) rendering, overwhelming mid-range GPU fillrate and VRAM bandwidth.
  - Added `MENU SUPERSAMPLING` in `SETTINGS > DISPLAY & SOUND > GRAPHICS`. When disabled (default), Noble renders at native 1:1 display resolution for optimal performance, saving up to 75% GPU fillrate and maintaining a locked 60 FPS in the launcher menu.
- **Background Scanner Thread Priority:**
  - Background memory scanning threads in `ReachArmory` are now set to `THREAD_PRIORITY_BELOW_NORMAL` to prevent background scans from competing with the main thread on 8-core / 16-thread processors.
