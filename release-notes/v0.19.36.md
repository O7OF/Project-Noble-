# Project Noble v0.19.36 Release Notes

## Robot Arm Chest Permutations & Crash Fix (`0xC0000005`)
- **Resolved Fatal Render Model Crash on Robotic Arm Chests:**
  - Diagnosed crash `0xC0000005` at `haloreach.dll+0x6950A9` (called via `ai_place` / unit spawn): when equipping chest pieces with prosthetic cybernetic arms (`Collar Grenadier [UA] [R]`, `Tactical Patrol [R]`, `Tactical Recon [R]`, `UA Counterassault [R]`, `Default [R]`), `ReachArmory.cpp` resolved `apply("44", sel.chest)` into the render model permutations (`player_john117` for male, `kat` for female), but immediately overwrote `perm["arms"]` with the literal string `"robot"`.
  - Because Reach's spartan render model has no permutation named `"robot"`, the render model index lookup failed or went out of bounds, causing an Access Violation crash when dereferencing the permutation block.
  - Corrected `perm["arms"]` resolution in `ReachArmory.cpp`: now maps prosthetic arm selections to `sel.isFemale ? "kat" : "player_john117"` and strictly guards against assigning the raw string `"robot"`.
  - Fixed fallback region mapping in `!pmcg` branch from invalid region `"hands"` to proper Blam! model region `"arms"`.

## Armory UI Flickering Elimination (Spartans & Elites)
- **Eliminated Biped Double-Rebuild Cycle:**
  - `SingleRebuild()` in `ReachArmory.cpp` previously returned `false` by default, activating a 45-frame delayed `bumpRebuild("settle")` after every selection click. This told Reach's `rr_armory` script to destroy and recreate the biped twice per change, causing jarring double-blinking.
  - Defaulted `SingleRebuild()` to `true` (requiring `-armory-settle-rebuild` command-line flag only if explicitly requested), eliminating the redundant recreate cycle.
- **Throttled Tag Shader Constant Writes:**
  - `UpdateTagShaderConstantsSEH` was previously scanning all ~32,000 tag elements and writing material floats (`rmsh`) into active tag memory every single frame during `ReachArmory::Update`. Doing this while the GPU rendering thread was drawing the 3D viewport caused constant buffer cache tearing and visible rapid flickering across both Spartan and Elite bipeds.
  - Added dirty-state caching in `WriteColorsAndSuit`: shader constants are now updated only when colors, visor tints, lights, species, or biped remade counters actually change.
- **Optimized Biped Permutation Tick Synchronization:**
  - Reduced `s_permSyncTicksRemaining` in `SyncArmoryLiveBipedEngineTickSEH` from 24 continuous frames down to 2 frames upon rebuild/permutation changes, preventing unnecessary repeated `SetRegionPermutation` calls.

## Multiplayer Per-Player Appearance & Color Isolation
- **Prevented Remote Player Loadout Overwrite (`IsLocalPlayerRecord`):**
  - In `src/engine/ElitePack.cpp`, `IsLocalPlayerRecord` previously contained `if (caller == kBuilderReturnLive) return true;`. Because `0x0447B0` can be called for any player biped in a match, remote players were erroneously identified as local machine players.
  - This caused the host's `BuilderHook` to overwrite remote peers' appearance records with the host's own armor pieces (`s_localPicks`), armor set (`s_localSet`), armor effect (`s_localEliteEffect`), and visor index (`s_localSpartanVisorIndex`).
  - Corrected `IsLocalPlayerRecord` to strictly inspect the player datum flags `((flags & 0x08) != 0) || (isLocalByte == 1)` for all caller sites. Remote clients now preserve their own replicated appearance records, armor pieces, species, and effects.
- **Team-Based vs FFA Gamemode Colors:**
  - Verified and preserved Halo: Reach's native team color logic: in team-based gamemodes (Team Slayer, CTF, Assault), `haloreach.dll`'s `0x2C63D8` automatically sets primary and secondary base armor colors to the assigned team color (Red/Blue/etc.).
  - In Free-For-All modes (Slayer FFA, Infection, Juggernaut, Forge), base armor colors use the player's personal custom chosen primary and secondary colors.
  - Visor colors (all 30 finishes) and undersuit/lights colors are preserved as each player's personal customization across both team and non-team multiplayer matches.
