# Project Noble Release Notes --- v0.20.9

### Scoreboard in every mode
- The scoreboard now seeds its roster from the lobby roster that launched the match (`-loading-roster`), so
  Campaign, Firefight, Custom Games, Forge, LAN and direct-connect matches show the real player names and
  marks your own row, instead of inventing "PLAYER n" rows or showing only the local player. A master-server
  session row (when present) still replaces it with richer data (tags, ranks, machine ids).
- Team columns stay mode-correct: Campaign and Firefight use the single unified co-op column, team columns
  appear only when the match actually has more than one team, and Forge has no scoring rows.

### Campaign join in progress (diagnosis + next step)
- The guest's black screen is a **crash**, not a render stall: the guest's match process faults at
  `haloreach+0x475D8E` (a null player-mapping entry) about nine seconds after the session starts. The engine
  logs `game net log: dscrd cnst:(null)` and a 53 KB state message immediately before the fault.
- The campaign host in the test was running a Steam Workshop campaign mod (`campaign.map` from workshop
  content). If the two machines have different versions of that mod, the state message cannot be decoded
  (discarded null constant) and the guest's object state diverges - which produces exactly this null
  mapping fault.
- Next: reproduce with an **unmodded** campaign join-in-progress to separate mod-content mismatch from the
  late-join insertion itself, then either sync the guest's campaign insertion point to the host's current
  checkpoint or guard the null mapping entry in the engine copy.
