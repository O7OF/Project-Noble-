# Project Noble v0.19.69 Release Notes

## Engine Limits & AI Actor Options Fix (Release & Dev Builds)

### Summary
This mini-update resolves an issue where selecting Engine Limit profiles (`Stock`, `Extended V16`, `Extended + Particles`, `Full`) and expanded AI actor pools (up to `1024 actors`) in the Settings menu could silently fail or fall back to stock behavior. The engine limits and actor pool expansions now work consistently across both Release (`noble-client.exe`) and Developer (`noble-dev.exe`) builds.

### Key Changes
- **Direct Runtime Engine Limit Profiling:** `EngineLimits.cpp` now seamlessly applies memory pool resizing and object table expansions directly to the active `haloreach.dll` module at launch without requiring external patch files (`.nlp`) on disk.
- **Dynamic Bank & Scheduler Patching:**
  - Game state memory allocations are now dynamically resized in-memory: Bank 1 (AI memory, +6MB) and Bank 3 (Render memory, +8MB).
  - Extended the AI scheduler and frame dispatch caps (0x200 cap expanded to 1,024 active actors) across all internal AI sub-schedulers.
  - Automatically hooks `data_array_new` (0x12FCC) when Extended V16, Extended + Particles, Full, or >96 AI actors are selected.
- **Live UI Feedback:**
  - The Settings menu (`ENGINE` section) now displays real-time confirmation of the active in-memory profile (`Active Profile: Stock / Extended V16 / Extended + Particles / Full`) and live actor pool capacity (e.g., `256 ACTORS`).
- **Release Packaging:**
  - Ensured `data/limits/` directory staging and proper executable packaging for portable distributions.
