# v0.19.55

## Campaign co-op: also keep the guest when the engine escalates to the co-op incompatibility boot

Two-player campaign co-op holds with this series. For a third player the engine ends the mission itself rather than
booting anyone, so the boot path is not the whole story - but while investigating it the actual decision was found:

`FUN_18044fc94` walks the session's peer mask and, for every peer whose player record (`+0x158` stride) carries the
campaign flag at `+0x17C` and whose `+0x118` field equals the id being checked, calls the boot helper
`FUN_180395090(session, peer, 9)` - i.e. the host boots peers whose campaign player record does not belong to the
session's own player. The previous build only ignored reason 9; the escalation code path uses 0x1B
(`error_players_incompatible_for_network_coop`) as well, which is now ignored for campaign co-op too.

Still open: with three players the engine sets its "game running" flag to 0 shortly after the third player spawns
(logged by v0.19.54's frame-numbered trace) and the mission ends. That needs the joining player's campaign player
record to match the host's, not a suppression.
