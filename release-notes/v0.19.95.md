# Project Noble Release Notes — v0.19.95

### Campaign

- **Campaign no longer black-screens after the intro cutscene.** The 145510a launch-block change skipped the host's player identifier (+0xF0) and slot descriptor for campaign/firefight. Without them the local player was never bound, the mission sat on a black frame and a skip left it there. The host fields are written for every mode again; all stock missions render and hand over to gameplay.
- **Noble Actual (m05) and Lone Wolf (m70_bonus) can finish.** They are cinematic-only, so the premature-end guard no longer holds the mission open after its cutscene.
- **5+ player co-op:** a campaign/firefight host whose roster is already over 4 now creates the session with capacity 8 (1-4 player launches keep their exact launch block).

### Networking

- **Real ping values for every player.** The match process now uses the machine id the lobby published, so scoreboard rows, per-peer mute and name lookups key the same id as the wire traffic. The fake round-robin/25 ms fallbacks are gone: an unmeasured row shows "-" instead of another player's RTT. The backend stores 0 for the host and -1 for unknown instead of inventing 25.
- **Lower non-host input latency:** duplicate filtering now only applies to relay copies (haloreach's repeated direct-UDP input packets were being dropped), held packets expire after 250 ms instead of replaying a 5-second burst, and a lapsed direct UDP route re-latches in 500 ms instead of 3 s.
- **Guest match-end crash:** leaving a match uses an exit-safe teardown that does not close the UDP socket under haloreach's network thread, and the host's match_over packet is handled on the UI thread instead of the relay thread.

### UI / Camera

- **Post-match buttons respond.** The container child no longer blocks on HTTP/WebSocket shutdown before handing the relaunch to the launcher, so RETURN TO MENU / PLAY AGAIN / RETURN TO LOBBY take effect.
- **Camera hitch fix:** the first/third-person camera hooks no longer deep-copy the whole settings object (maps/strings under a mutex) every frame; the six camera fields are cached and refreshed 4x/sec.
- **No more double camera tuning:** the two third-person update hooks can both run for the same observer command in one frame; tuning now applies once per command per frame, only for local user 0. The vehicle cockpit path only runs when vehicle first person is on and 3rd-person tuning is skipped while it owns the camera, so offsets/FOV no longer compound.
