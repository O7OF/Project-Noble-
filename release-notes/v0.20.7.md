# Project Noble Release Notes --- v0.20.7

### Firefight join in progress (base maps)
- Your log shows the host calling `AbortGame(reason=6)` 11 ms after the joining player's session channel
  closed. That abort ends the host's Firefight match, the joiner's reconnect is then refused, and the
  client drops to the main menu.
- `AbortGame(reason=6)` is now suppressed while a Noble network transport is active, so the host's match
  keeps running and the engine's join handshake can insert the late player. The suppression is logged
  (`SUPPRESSED AbortGame(reason=6) for join-in-progress`) so a genuine failure is still visible in the
  dev log.
- Refusals for other reasons (session full, version mismatch, kicked) still go through, as before.

### Settings reset to default
- Fixed the start-up migration copying a stale `settings.json` from `Documents\Noble Launcher\data` or
  `%APPDATA%\ProjectNoble\data` over the saved file. Migration is now first-run only.

### Earlier in this line
- Guests see the full loading roster and player count; single "YOU" on the scoreboard; per-player service
  tags; joiner ping; invite direct-connect with the real host name; server-browser version matching the
  main menu; AMD CPU power/priority changes.
