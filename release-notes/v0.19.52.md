# v0.19.52

## Campaign co-op: the host no longer boots the guest at spawn

Joining a campaign mission ended a few seconds after both players spawned with "Error hosting co-op". The logs show
exactly what the engine did: a few seconds in, the host calls its peer-boot path with **reason 9** (campaign progress
incompatible for network co-op), sends session-boot to the guest, the guest leaves the session and both clients report
the failure.

That boot is now dropped while a campaign co-op mission runs, so both players stay in the mission. The engine
re-evaluates it every frame; the decision is left logged once per session and the rest is silent.

`NOBLE_COOP_NO_KEEP_PEER=1` restores the old behaviour for comparison.

Verified locally with a host and a guest on the same PC: before, both clients ended at the boot; after, the session
stayed up (running for minutes, frames advancing) instead of raising the co-op error.

Still open: the guest joins at the map's default insertion instead of the host's checkpoint, which is the same
campaign-progress mismatch underneath this boot. Sharing the host's checkpoint with the guest is the proper fix and
the next step for co-op.
