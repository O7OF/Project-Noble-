# Project Noble v0.19.75 Release Notes

## Summary
- **Unified Master Server Architecture (Global Main):**
  - Migrated the master server infrastructure to `https://projectnoblebackend.onrender.com` as the sole primary backend.
  - Removed deprecated regional cluster endpoints (`projectnobleeast`, `projectnoblewest`, `projectnobleuk`) from the client and server registry mesh.
  - Simplified the in-game Server Browser region selector to "Global Main Master Server" and "LAN / Offline Only", with automatic legacy settings migration to the new endpoint.
  - Persistent `/var/data/database.db` backend storage on Render manages accounts, user IDs, and developer/tester roles cleanly within server disk quotas, while career progression and appearance remain local.
- **Dynamic Developer & Tester Role System:**
  - Removed the requirement for separate developer binaries (`noble-dev`); developer tools and mod menus are now compiled directly into the release binary and dynamically gated by the backend account role (`is_developer`).
  - Added full support for the `[TESTER]` role and tag across both the backend and client.
  - Added dedicated CLI tools in the backend repository: `set_tester.js` (`node set_tester.js <username> [--create|remove|list]`) and enhanced `set_dev.js`.
  - Added cyan `[TESTER]` tag rendering on player nameplate rows and a dedicated `TESTER` status chip in the Account Modal (`DrawAccountModal`).
  - Dynamic role refresh on presence heartbeats and via background queries to `/api/dev/check`.
- **Runtime-Gated Developer Console & In-Game Cheats:**
  - In-game Developer Cheats & Mod Menu (`+` / `Numpad +`) and `Hook_Tick` stress tools are now runtime-gated by `AuthClient::Get().IsDeveloper()`, ensuring standard players have zero overhead and preventing unauthorized activation while keeping the client binary unified.
