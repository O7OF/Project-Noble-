# Project Noble v0.19.43 Release Notes

## Campaign: Lone Wolf and Epilogue loaded the wrong mission
- **Overlapping mission stems.** `BlamEngine::ResolveMapId` tested `"m70"` before the two extra m70 scenes, and
  the names overlap: `m70_bonus` (Lone Wolf) contains `m70`, so Lone Wolf launched as launch index **187 (The
  Pillar of Autumn)**. Epilogue (`m70_a`) had the same collision. The specific scenes are now matched first:
  `m70_bonus` -> 189, `m70_a` -> 188, then `m70` -> 187.
  - Verified: Lone Wolf now loads the authentic block `campaign_189_d1.bin`.

## Campaign: ONI: Sword Base stalled on its own donor map
- **The AI/object donor was hard-coded to `m20.map` (Sword Base).** The cross-map tag cache maps the whole campaign
  map as a zero-copy view at startup; launching ONI: Sword Base therefore mounted **m20 twice** (donor and mission)
  and the mission never got past `LoadProgress 4%` — the engine sat with no resolvable scenario and the launcher
  kept returning to the menu (an apparent infinite retry loop).
  - `SharedTagCache::SetAvoidMap(launchMap)` is now called before the cache initialises, and
    `DiscoverDonorMap` skips any candidate whose scenario stem is the map being launched (including the workshop
    `m20.map` fallback scan), falling through to the next donor (`m45`).
  - Verified: the session starts at frame 302 and ONI: Sword Base plays normally.
