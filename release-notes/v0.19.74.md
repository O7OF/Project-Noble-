# Project Noble v0.19.74 Release Notes

## Summary
- **Post-Match Screen Responsiveness & Crash Fix:**
  - Converted lobby state synchronization in `FrontEndMenu` to an asynchronous background worker thread, eliminating synchronous WinHttp stalls that previously caused the UI to freeze ("Not Responding") and frame rate to tank when returning to the lobby.
  - Resolved non-host and host crashes when clicking post-match buttons by decoupling lobby teardown into detached background threads and eliminating premature network transport teardowns while the engine thread is active.
  - Enabled DirectX 11 multithread protection (`SetMultithreadProtected`) and synchronized `Present` calls inside `HoldFrame`, preventing driver crashes (`nvwgf2umx.dll` access violations) during match end transitions.
- **Mid-Match Join-In-Progress ("Loaded in the Chamber"):**
  - Pre-allocated player slots 1 through 15 with unassigned slots in the host launch block, ensuring player indexing is preserved and allowing clients to direct-connect mid-match without encountering "Error hosting co-op".
  - Patched `SetSlotCounts`, `AcknowledgeJoinRequest`, and `SessionAbort` hooks to allow seamless mid-match joins and prevent session drops during active gameplay.
  - Accelerated direct-connect guest handshake settling (500ms fast settle), bypassing unnecessary relay wait times.
- **Server Browser In-Progress Match Tracking:**
  - Live simulation state is now dynamically pushed to the master server, allowing active matches to display properly in the server browser with an amber `[IN PROGRESS]` status badge.
- **Campaign Lockstep & Netcode Latency Optimization:**
  - Direct UDP peer confirmation is now immediately established upon peer addition in `NetworkTransport`, eliminating relay fallback latency for direct connections.
  - Expanded immediate packet flushing in `ObserverChannelSendMessage` to cover all synchronous lockstep input and update packets (`0x1F..0x30`), dramatically reducing campaign input latency.
