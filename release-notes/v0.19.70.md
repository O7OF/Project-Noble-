# Project Noble v0.19.70 Release Notes

## AMD GPU Draw Call Optimization, Frame Pacing Fix & Crash Protection

### Summary
Version 0.19.70 fixes a framerate drop issue where AMD Radeon graphics cards (such as the RX 5700 XT) experienced framerates falling to ~47 FPS due to D3D11 multithread protection overhead and software-versus-hardware VSync pacing collision. In addition, this release ensures stock DLL engine limit stability (eliminating crashes on stock DLL allocations), and incorporates active null-object dereference safety in the Blam! simulation loop.

### Key Changes
- **AMD Radeon Draw-Call Throughput Optimization:**
  - Disabled `ID3D11Multithread::SetMultithreadProtected` on the immediate context. Halo: Reach and Noble's overlays execute strictly sequentially on the dedicated render thread; disabling global context lock acquisition eliminates driver-level mutex contention on AMD GPUs (`atidxx64.dll`).
  - Tuned DXGI frame latency to prevent AMD Command Processor pipeline stalls while preserving low input latency.
- **Hardware VSync Frame Pacing Synchronization:**
  - Resolved double-pacing conflict in `HookSwapChainPresent`: when hardware VSync is enabled (`verticalSync: true`), software sleep/yield loops are bypassed for 60+ FPS targets, ensuring the render thread never misses display VBlank deadlines (which previously caused 60Hz displays to alternate frames and drop to ~47 FPS).
- **Stock Engine Limits & Settings Crash Elimination:**
  - Resolved fatal `0xC0000005` access violations when opening the Settings screen or launching with non-default engine limits (`extendedLimits: 1..3`, `aiActors: 1024`):
    - Safely scaled the `object` pool from 2,048 to **32,767** in memory on stock DLLs without overflowing master memory banks.
    - Prevented unpatched stock DLLs from resizing GPU particle tables that require offline PE sections.
    - Added `ActiveActors()` getter to accurately reflect active actor pool capacity in the Settings UI.
- **Engine Simulation Null Object Guard:**
  - Trampoline guard at `haloreach.dll+0x99A0D` safely catches and skips null biped/datum lookups during Campaign checkpoints, autosaves (`asq_campaign_m10`), and cutscene transitions.
