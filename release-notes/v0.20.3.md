# Project Noble Release Notes --- v0.20.3

This release is a build-hardening and diagnostics release. The shipped client is now harder to reverse
engineer, and player-facing diagnostics are split cleanly between the development build and the release.

### Anti-Reversing Build
- **No symbol files ship:** the release executable no longer produces a `.map` or `.pdb` beside the program. The development build keeps its map for crash analysis.
- **Hardened code generation:** the release client is built with aggressive optimisation, COMDAT folding, and RTTI removed, so function boundaries and type information no longer line up for a decompiler.
- **Obfuscated string literals:** backend endpoints, the master-server default, the engine module name, and the engine window class are encrypted at compile time and decrypted on the stack at use, so they no longer appear as plain text in the binary.
- **Optional maximum optimisation:** a packaging build can enable whole-program optimisation with `-DNOBLE_LTO=ON`; the default build is deliberately faster to compile.

### Logging & Diagnostics
- **Development builds are the only ones that write a log.** `noble-dev.log` keeps the full trace for bug reports.
- **Release builds write no log at all.** If the game crashes it writes `noble-crash.dmp` next to the program; the settings screen now points at that file and the "copy diagnostics" action reports its presence.
- **Diagnostic strings are compiled out of release**, so the shipped binary no longer contains internal trace messages.

### Build
- **Faster iteration:** the release client no longer uses whole-program optimisation by default, which cuts a clean build from many minutes to a couple of minutes. Use `-DNOBLE_LTO=ON` for a final packaging build.
- Parallel compilation (`/MP`) is enabled for the client target.
